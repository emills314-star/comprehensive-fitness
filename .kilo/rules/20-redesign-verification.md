# Redesign verification rules

- Inspect the running application; source inspection or passing tests alone are not visual evidence.
- Use fabricated data and isolated browser state only.
- Check at 390×844, 430×932, 768×1024, and 1440×900.
- Exercise Today, optional readiness, direct Start, active workout, prior performance, set entry including RPE 7.5, set completion, rest timing, substitution, actual-work edits, interruption/resume, completion, Progress, Routines, Settings, Support, and Privacy.
- Verify loading, empty, disabled, error, offline/recovery, keyboard, reduced-motion, contrast, focus, touch targets, overflow, clipping, chart behavior, and console output.
- Compare every proposal with the final product documents and name the protected behavior and regression risk.
- Use shared tokens and reusable primitives before one-off styling. Do not replace real behavior with static mocks.
- Run focused checks after each phase and the public gate plus Playwright before claiming completion.
- Keep root web sources and `www/` packaging outputs synchronized only through the repository command; advance the service-worker cache when a runtime contract changes.
- Update governing documentation and `docs/ROADMAP.md` with any integrated application change. Label unresolved conflicts `NEEDS REVIEW`.
- Never claim physical iPhone notification, sound, vibration, keyboard, lock-screen, suspension, deployment, migration, or visual-baseline acceptance without direct evidence.
