# Kimi session 1 — global design system

Act as principal product designer, not implementation engineer. Read `KIMI_DESIGN_CONTEXT.md`, `KIMI_DESIGN_AUTHORITY.md`, `AGENTS.md`, the ranked authoritative product docs, and supplied baseline screenshots. Analyze only the rendered current product. Do not perform broad code edits.

Define a premium, focused, restrained, modern athletic system that is fast under fatigue and data-rich without feeling clinical. Evaluate typography, spacing, density, surfaces, borders/elevation, backgrounds, controls, tabs/navigation, exercise/set rows, rest, dialogs/drawers, factual progress, completion, loading, empty, warning, error, disabled, focus, and responsive states. Avoid generic SaaS dashboards, card/border excess, oversized controls, empty acreage, explanatory clutter, gratuitous gradients, and novelty.

Create `KIMI_GLOBAL_DESIGN_SPEC.md` with concrete tokens, reusable component rules, responsive rules, accessibility notes, and prioritized changes. Do not implement.
