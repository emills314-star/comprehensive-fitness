# Kimi K3 design context

## Product

Comprehensive Fitness is Erik's local-first workout logger: “Strong with a quiet spotter.” The normal job is to open Today, identify the expected routine, start, see prior comparable work and stable targets, enter load/reps/decimal RPE, complete sets, rest, finish, and review factual progress. Normal training stays quiet; only direct recorded pain/injury or illness currently produces a live exception action.

The only persistent destinations are Today and Progress. Active workout is full-screen. Routines and Settings are contextual secondary surfaces. Mesocycles, volume dashboards, themes, numeric fatigue/readiness/plateau systems, and ordinary progression prescriptions are retired.

## Architecture

- Static PWA with classic JavaScript modules; no React/Vue/Svelte or bundler.
- Semantic CSS and shell markup live in `index.html`.
- HTML renderers and shared helpers form the component system.
- Hash/destination routing; delegated `data-action` events in `app.js`.
- IndexedDB/local-first state, versioned backup/schema contracts, service worker, active-draft recovery, optional push integration.
- Root assets are source; `www/` is generated by `npm run sync:web` and verified by `npm run verify:pwa`.
- Playwright is the browser/e2e framework and uses synthetic fixtures.

## Protected logic

- Stable prescriptions and compatibility: `prescription-engine.js`.
- Sole live exception rule: `exception-resolver.js`.
- State, persistence, validation, migrations: `app-foundation.js`, `backup-contract.js`, `schemas/`.
- Workout mutations and active draft: `app-workout.js`.
- Submission, immutable history, grades, PR facts: `app-history.js`.
- Strong import/export: `app-import.js`.
- Rest timer, push, service worker integration: `app-sync.js`, `rest-completion-controller.js`, `sw.js`.
- Factual progress: `app-analysis.js`.

Kimi must not redesign these algorithms. If a visual recommendation conflicts with them, Codex preserves behavior and implements the closest safe presentation.

## Existing visual concerns

The app is already a two-destination light UI. Review should focus on hierarchy under fatigue, density of set entry, unmistakable current/completed/untouched states, persistent rest awareness, long exercise names, compact secondary navigation, responsive overflow, and consistent completion/empty/error presentation. Historical concept mockups are advisory only; final redesign docs are authoritative.
