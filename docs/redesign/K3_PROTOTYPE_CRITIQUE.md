# K3 prototype critique

The combined nine-image vision request completed its analysis but emitted no final response. Following the bounded retry rule, K3 reviewed each direction separately. The complete authority output is preserved in:

- `K3_PROTOTYPE_CRITIQUE_LOGBOOK.md`
- `K3_PROTOTYPE_CRITIQUE_SPOTTER.md`
- `K3_PROTOTYPE_CRITIQUE_SPINE.md`

## Critical correction summary

- **Logbook:** the first pass did not achieve its density premise; duplicated workout chrome consumed the viewport; the bottom session dock overlapped content and displaced the specified rest treatment.
- **Spotter Cards:** the floating dock clipped Today content; the idle/rest ballast was absent; completed-set chips omitted performed facts.
- **Session Spine:** the spine was decorative rather than per-set; rest was not structural; Finish was duplicated; desktop Progress compressed its chart to an unusable width.

## High correction summary

- Remove duplicate global/session headers and consequential actions in workout views.
- Flatten readiness-like “Ready / Your work is set” hero language.
- Preserve recorded facts in completed-set treatments.
- Expose an exact-variant selector and the explicit recent/all-history choice in Progress.
- Make per-set rest controls visibly interactive.
- Correct each direction’s navigation geometry without adding destinations.

Codex applied all Critical corrections and the aligned High corrections to the design lab before the final comparison capture. Medium issues were applied where low-risk: quieter progress controls, fact-first history rows, improved dock sizing, and stronger non-color state markers. Protected product behavior was not changed.
